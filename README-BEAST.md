# THE BEAST — Autonomous Web Studio (v2.0, final)

An app that designs and builds complete, sellable websites on its own — one deliberate
stage per day — and stamps your copyright on every page. Download the finished sites as
ZIPs, clear the shelf, and the Beast starts the next commissions immediately.

**Status: finalized.** 23/23 features verified by the built-in test suite
(Test Center tab, or `bun scripts/test-beast.ts`).

## What it does

- **Daily website production.** Three commissions run in parallel; each crosses
  7 deliberate stages (brief & research → colour & type lock → wireframe D1–D5 →
  build & markup → micro-polish → QA · C.R.A.P. audit → © stamp & publish).
  Progress is calendar-based: close the app for three days and it has three days
  of work done when you return (missed days replay automatically on wake-up).
- **One site, five devices, five different relative layouts.** D1 phone (≤640, 1-col
  stack, drawer nav, poster hero, sticky CTA bar) · D2 tablet (641–1024, 2-col,
  condensed nav, centered hero) · D3 laptop (1025–1440, 3-col, split hero 55/45) ·
  D4 desktop (1441–1920, 4-col, mega footer + stats) · D5 ultra/TV (≥1921, 5-col,
  cinematic monumental hero). These are structural re-arrangements — not zoom
  levels. Built from relative units only: %, fr, clamp(), rem, aspect-ratio.
  The preview dialog switches devices live.
- **Infinite possible sites.** Seeds drive a combinatorial grammar: 6 harmony
  formulas × 360 hues × 3 themes × 99 font pairs × 6 heroes × 4 navs × 7 motifs ×
  radii/rhythm/eyebrow/case × 6,720 section orders × 12 niches × naming grammar ×
  copy picks — roughly 10^24 years of daily output without a repeat. Same seed ⇒
  identical site, forever (determinism is tested).
- **Measured design decisions.** Palettes are generated by harmony math, then
  contrast-corrected per role until they clear WCAG (ink ≥ 7:1, soft ink ≥ 4.5:1,
  accent ≥ 3:1, text-on-accent ≥ 4.5:1). Text-on-accent is solved on the accent
  axis itself — midtone accents are pushed to an extreme instead of guessing.
- **Dark mode done properly.** Light/duotone sites carry a `prefers-color-scheme`
  block whose tokens are re-derived (not inverted) and re-passed through their own
  WCAG check; natively-dark sites declare `color-scheme: dark`. Motifs are painted
  with token vars + color-mix so the whole surface re-tints automatically.
- **The Layout Book.** Twelve fully specified page layouts (exact container widths,
  columns, gutters, breakpoints, reading patterns) with citable sources: NN/g
  eyetracking, Material Design, MDN grid recipes, Setproduct bento math,
  Müller-Brockmann. Selected per seed at the wireframe stage.
- **The 12-book education.** The design canon distilled into doctrine + executable
  machine rules; the engine consults each book at its matching stage and cites it
  in the work log (Krug, Norman, Wathan & Schoger, Garrett, Müller-Brockmann,
  Lupton, Albers, Williams, Tidwell, Lidwell et al., Kleon, Unger & Chandler).
- **C.R.A.P. audit** (Robin Williams): Contrast / Repetition / Alignment / Proximity
  computed with real numbers before anything ships; the QA record is stored per site.
- **Launch-ready support pack.** Every site ships with `index.html` +
  `sitemap.xml` + `robots.txt` + `404.html` + `DESIGN-NOTES.md` (palette WCAG
  tables, structure, device law, C.R.A.P. results, buyer launch checklist) +
  `LICENSE.txt` + `README.txt`. Swap the domain, upload to any static host,
  submit the sitemap — sellable as-is.
- **Your copyright everywhere.** Footer stamp with live year, LICENSE.txt,
  DESIGN-NOTES.md, ZIP README. Rename the owner in Settings and every shelved
  site re-stamps instantly.
- **Download → clear → repeat.** Per-site ZIP or the whole shelf in one archive
  with a catalog. Clear the workspace after download; the next work day starts
  fresh commissions. The queue never empties.
- **Self-healing engine.** Sites are re-rendered from their seed whenever the
  engine version moves — upgrades flow into everything already on the shelf.
- **Test Center.** A feature-by-feature verification suite (23 checks across
  generator, design knowledge and engine) runs in-app against a throwaway
  sandbox — never touching live state. Same suite: `bun scripts/test-beast.ts`.

## Quickstart (Bun)

```bash
bun install
bun run dev             # http://localhost:3000
bun scripts/test-beast.ts   # run the 23-feature verification suite
```

The studio wakes up with 9 simulated days of work already done (one site on the
shelf, two mid-pipeline). Press **Force work day** to watch the next stage finish.

## Quickstart (Node)

```bash
npm install
npm run dev             # next dev -p 3000
```

## Production

```bash
bun run build
bun run start
```

## Settings

- **© Copyright owner** — type your name in the header field; every site re-stamps.
- **Force work day** — run the next day immediately (everything else stays calendar-driven).
- **Download all / Clear** — take the shelf, then empty it.

## Where things live

| Path | Purpose |
| --- | --- |
| `data/beast-state.json` | studio state (day, sites, log) |
| `data/sites/<id>/` | built site files (index.html + support pack) |
| `src/lib/beast/spec.ts` | device classes D1–D5 + content grammar (the law book) |
| `src/lib/beast/render.ts` | seed → complete standalone site + support pack |
| `src/lib/beast/palette.ts` | harmony math + WCAG correction + dark tokens |
| `src/lib/beast/layouts.ts` | the 12-pattern Layout Book |
| `src/lib/beast/knowledge.ts` | the 12-book education + 7 stages |
| `src/lib/beast/engine.ts` | daily work loop, ZIPs, workspace ops |
| `src/lib/beast/selftest.ts` | the 23-feature verification suite |

## API

| Endpoint | Purpose |
| --- | --- |
| `GET /api/beast` | studio state (auto catch-up on missed days) |
| `POST /api/beast` | `{action: skip \| clear \| setOwner}` |
| `GET /api/beast/site/[id]` | a built site's HTML (self-healing) |
| `GET /api/beast/site/[id]/zip` | per-site ZIP with support pack + license |
| `GET /api/beast/zip-all` | whole shelf + catalog.txt |
| `GET /api/beast/test` | run the 23-feature suite |
| `DELETE /api/beast/site/[id]` | remove one site |

## Provenance

Patterns adapted from `abbylukwa/whatsapp-qr-app` (API key-slot pool → parallel
studio slots; resource registry → site records; cool-and-revive → non-blocking
queue). Real key values were never copied — structure and patterns only. Notes:
`download/beast-research/api-key-notes.md`.
