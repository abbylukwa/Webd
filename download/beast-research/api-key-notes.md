## 2. 编号槽位池模式（env.example 的核心设计）

```
API_1…API_8 = <masked>        # 8 个编号槽位，粘贴任何供应商的 key
```
- **按形状自动识别供应商**：`sk-or-v1-…`→OpenRouter；`sk-rewind-…`→Rewind（先于 `sk-` 判定）；`sk-…`→OpenAI；其他→默认端点
- **任务分配**：round-robin 轮询，每个任务发给"下一个健康"的供应商；1 个可用 = 单线程，5 个可用 = 并行拆分
- **冷却与复活**：失败两次 → 冷却 5→30 分钟 → 恢复后自动复活，随时可增补/替换密钥
- 每槽位可覆盖：`API_1_NAME` / `API_1_URL` / `API_1_MODEL`
- 遗留命名键（`REWIND_KEY`、`OPENAI_KEY`）自动并入同一个池

## 3. 密钥注册表模式（config/api-keys.json）

```jsonc
{
  "keys": [
    {
      "name":      "<masked>",
      "assignTo":  "<masked>",   // 绑定给哪个执行体
      "scope":     ["…"],        // 作用域白名单（_scope_options: all/…）
      "priority":  90,           // 数字越大越优先被调度
      "provider":  "<masked>",
      "freeLimit": 0,            // 免费额度跟踪
      "costInfo":  "<masked>",
      "description": "<masked>"
    }
  ]
}
```
要点：密钥不是散落的字符串，而是**带元数据的资源对象**（作用域/优先级/成本/额度），由统一调度器消费。

## 4. 会话持久化模式

- 部署会清空磁盘 → 用 `SESSION_B64_GROUPS` 环境变量做 base64 会话备份，启动时自动恢复（"永不再扫码"模式）

## 5. 对 Beast Web Developer 的吸收

1. **密钥池 + 优先级 + 冷却复活** → 直接借鉴进生成引擎的任务队列设计（多任务不赶工：槽位 = 并行工地，失败不阻塞其他站点）
2. **密钥即资源对象** → Beast 的每个"站点工程"也是资源对象（种子/阶段/日志/价格），而不是散落文件
3. **环境变量注入 + 形状自识别** → Beast 的配置（版权署名、并发数）走同一模式，缺省可空
4. 安全红线：任何真实密钥不入库、不展示、不打进生成的站点
